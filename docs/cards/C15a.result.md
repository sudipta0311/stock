## Decisions / open issues
- `fundamentals_pit` adds `known_at` to its primary key so changed filings can be retained as separate versions. The card’s listed key without `known_at` cannot store multiple versions of the same security, metric, period, and source.
- Consecutive repeats keep the first filing date, `known_at`, and source URL. A value that returns after an intervening restatement gets a new version row.
- S&P 500 membership uses State Street’s [daily SPY holdings workbook](https://www.ssga.com/us/en/institutional/library-content/products/fund-data/etfs/us/holdings-daily-us-en-spy.xlsx), whose embedded holdings date is parsed by the loader. NIFTY 500 uses NSE’s [archive CSV](https://archives.nseindia.com/content/indices/ind_nifty500list.csv). No constituent CSV was committed. Both loaders mark membership as `current constituents only (survivorship bias)`.
- NSE’s public filing index and XBRL files were reachable without login, and the adapter is implemented. The observed filing history is shorter than 11 years; a licensed backfill provider would need to supply quarterly and annual values, period type/end, filing and revision timestamps, units, consolidated status, and source-document URLs.
- The 230 MB estimate assumes 10% extra version rows and the measured average row/index size. It is new-table usage only; production’s existing usage was not measured against Neon’s 0.5 GB cap.
