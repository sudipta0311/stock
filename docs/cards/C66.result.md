# C66 result
## Summary
- Inside the 30-second grace window, presenting the previous refresh token now issues a fresh pair (new access token, new refresh token) instead of 409, so a lost renewal response no longer signs the person out.
- The re-issue keeps `previous_hash`, and does not move `last_used_at` or `expires_at`, so repeating the old token cannot stretch the window; after it, reuse still revokes the session and writes one `auth_refresh_reuse_detected` audit row.
- The re-issue path applies the same checks as a normal renewal: expired or absolute-expired → 401, email no longer allowed → 403 with revocation.
- 409 stays documented on the route for older PWA builds.
