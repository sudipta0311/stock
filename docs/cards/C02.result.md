## Rework

- `parse_inr` now returns a Decimal quantized to two places. Rupees fields normalize text, integer, and Decimal inputs and serialize as fixed-point strings; rate fields serialize without exponent notation.
- Compact INR formatting now selects lakh or crore after half-up rounding. Regression cases cover both unit transitions and larger crore boundaries.
- Exported money and rate schemas now use the canonical decimal string patterns and INR/range extensions. The export strips the OpenAPI-only union discriminator so the output uses standard JSON Schema keywords plus `x-*` extensions.
- Added `jsonschema>=4.23` to the dev extra. Tests validate every exported file against Draft 2020-12, validate one serialized example for each asset type, and reject exponent-form and negative principals.
- Reran every C02 acceptance command after the fixes; all passed.

## Decisions / open issues

- An NPS mix is accepted only when all four percentages are supplied and sum to 100; when no mix is supplied, sleeve defaults use a 50/50 equity/debt split.
- The coarse `within_1y` class represents bonds and exchange-traded or digital gold; assets with no liquidity detail in the catalogue map to `locked`.
