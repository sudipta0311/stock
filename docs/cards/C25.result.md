## Reviewer notes
- **Partner account deletion failed (found in review, older than this card).** The `app.household_deleting_user` skip never applied: `mark_user_deleting` sets it inside a function with its own SET clause, and PostgreSQL reverts it on return. So when a partner deleted their account while their own space was open, the cascade removing a note they had hidden in a family plan logged them as the actor after their users row was gone. The audit insert then failed its foreign key, and deletion returned 503. Cascade AFTER triggers fire at depth 1, so a `pg_trigger_depth()` check doesn't catch this. Migration 0026 now also replaces `audit_highlight_dismissal_write`, and both audit functions skip once the actor's users row is gone. Downgrade restores the 0011/0015 bodies. Test: `test_a_partner_can_delete_their_account_with_notes_hidden_in_the_family_plan`, which fails at 0025 and with the card's original 0026.
- **EPF part-year:** the card's version counted the current month as fully earned (on 2 January, January's interest and contribution were included). EPFO credits interest on month-end balances, so a month now counts once it has ended. The full-FY example is unchanged (₹88,702.76). Added mid-month checks (30 Apr and 15 May both give ₹6,875.00) and changed the 15 Jan expectation to 9 months.
- **Profile check retry:** `verifyProfile` moved to `queryClient.fetchQuery`, which picks up the client default `retry: 1`. A 401 would have been retried before signing out, and a waking server would have waited 150 s twice. Set `retry: false`.
- **Docs:** README privacy note corrected (statements from the Gmail helper wait in the inbox until read; saved statement passwords are encrypted), Gmail helper added to the layout, Denmark mentioned. Card index: corrected `legacy/` references (no code or test imports it; only config and docs name it), research activation status (live smoke passed 2026-10-30; `SEC_USER_AGENT` needed for US scores), and 0026/EPF evidence.
