## Market and currency decision points

1. `rules/brokers.yaml` is the broker default table. `broker_defaults()` reads it; `load_layouts()` supplies those defaults to layouts unless a layout overrides them. The upload route resolves “Other” against the selected account institution, then carries the chosen defaults into auto-mapped and saved layouts.
2. `mapping_default_requirements()` uses `_market_without_default()` and a valid explicit currency to decide whether the mapping screen should ask for market or currency defaults. The user's answers are carried by `template_layout()` and saved with the household template.
3. `_market_without_default()` checks a valid row market first. If absent or invalid, a check-digit-valid ISIN prefix maps `IN`, `US`, `DK`, or `GB` to that market; any other valid ISIN maps to `EU`. If neither source works, `_row_market_currency()` uses the selected layout's broker/template default.
4. `_row_market_currency()` is called by both `parse_holdings()` and `parse_tradebook()`. It uses an explicit recognized currency first; otherwise `IN` maps to INR, `US` to USD, and `DK` to DKK. Other markets use the layout currency default. Unsupported final market/currency pairs are skipped.
5. `parse_cash_flows()` uses an explicit currency or the layout currency default; cash-flow rows do not infer a market.
6. The specialized IBKR activity parser in `wealth/importer/brokers/ibkr.py` keeps the statement currency and derives market from exchange: Copenhagen venues map to DK, Xetra/Frankfurt/Euronext to EU, London venues to GB, and other venues follow its USD/US or EU rule.
7. At confirmation, `_security_for_confirmation()` uses the staged row market/currency. Its legacy fallback, if either is missing, chooses IN for an IN-prefixed ISIN and US otherwise, then INR for IN and USD for other markets. When an ISIN already belongs to a security, confirmation links that existing security unchanged.

## Production fix (2026-11-04): INDmoney holdings export
- **The file never got past reading.** INDmoney's `.xlsx` declares its sheet as just `A1` (`<dimension ref="A1">`). Excel ignores the tag, but openpyxl's read-only mode trusts it, so the importer saw only the title cell and reported no header row. `_rows_from_xlsx` now calls `reset_dimensions()` on each sheet.
- **Funds were filed as shares.** The export has no type column, so VOO and QQQM became `equity`. Look-through only applies to `etf`/`mf`, so the companies inside them would have looked not-owned to Ideas. With no type column, a row is now an ETF when its name contains the word "ETF", its US symbol is in `rules/fund_lookthrough.yaml` `by_us_symbol`, or its ISIN is a curated EU ETF. The symbol upsert overwrites `security_type`, so a re-import corrects earlier rows.
- The parser now imports `wealth.policy.lookthrough.load_lookthrough_rules`, a YAML-only loader.
