## Bugs found and fixed

1. **Fund monthly amount broke household reads — app bug.** `InvestingPrefs` now declares a validated security-ID-to-positive-rupee override, and `fund_check.py` reads and writes it through the schema. Other `member.investing` writers were checked against declared fields. The API test saves an override, reads `/v1/me`, `/v1/members`, and `/v1/plan`, and verifies the fund check returns the saved amount.
2. **Dialogs violated the CSP — app bug.** Confirmed `react-remove-scroll-bar` (through Radix Dialog) injects the phone-size style. The app stylesheet supplies the body scroll-lock rule, and CSP allows the exact library-style SHA-256 hash. Tests compute the hash from the library output, require the quoted source form, reject `unsafe-inline`, and check scroll locking with no dialog console errors.
3. **Consent checkboxes did not respond immediately — app bug.** Every notification consent checkbox updates optimistically, stays disabled while saving, and rolls back with a short message on failure. Vitest covers the behavior.
4. **Loan updates displayed raw rates and dates — app bug.** Loan pages now show percentages with at most two decimals and no trailing zeroes, plus the app's usual date format. Vitest checks `4.8%` and the formatted date.
5. **Partner settings requested owner-only lists — app bug.** Invite and access requests are gated by the API's `_require_owner` role rule. Vitest verifies a partner makes neither request.
6. **Rebuilding an identical completed action could reopen it — app bug.** The plan store now matches completed actions as well as proposed actions, preserving the ID and status for an unchanged action. A DB regression test saves the same plan twice and checks that its completed action remains completed.
7. **Import row checkboxes waited for the server — app bug.** Selection is optimistic, disabled during the save, and restored with a short error on failure. Vitest covers the pending state and rollback.
8. **Settings helper text missed WCAG AA contrast — app bug.** Signed-in-device list metadata uses the existing foreground token on the muted surface. Vitest asserts the accessible token is applied.
9. **Tour progress dots used prohibited ARIA attributes — app bug.** The tour now exposes a progress list with the current step on its list item, announces “Step n of 4,” and hides decorative dots from assistive technology. Vitest includes an axe assertion.
10. **An invalid rate field could stay hidden — app bug.** When the API returns a field error, the asset form opens its optional-details disclosure and focuses the first invalid field. `rate_needed` explains that the official rate is unavailable and asks the person to use the certificate rate. Vitest checks the hidden field is revealed and focused; the E2E test enters a synthetic rate.
11. **Refresh throttling looked like an offline failure — app bug.** Refresh retries HTTP 429 responses using `Retry-After`, capped by the existing backoff and retry window. If rate limiting persists, sign-in shows a temporary-busy message instead of an unreachable-server message. Vitest covers the capped wait and persistent 429 state.
12. **Ideas card text and chips missed WCAG AA contrast — app bug.** Muted text inside the idea, Denmark, and fund cards now uses the existing foreground token. Market labels use the quieter `text-foreground/80` tint, which still passes contrast. The matching muted chip pattern was checked across other screens; no other text chips use it. Vitest runs axe on the expanded idea and fund cards.
13. **Partners saw viewer-only help — app bug.** Household settings now show viewers the view-only explanation and partners a separate owner-only invite/access explanation, while keeping the partner leave control. Vitest checks owner, partner, and viewer behavior.
14. **Queued offline edits were missing from the banner after navigation — app bug.** Offline status refreshes its queue count on route changes and shows the pending count inside the offline banner. IndexedDB writes resolve only after transaction completion, so the pending-change event follows a committed write. Vitest covers the banner and queue notification; E2E checks the banner, PATCH replay, and persisted value after reload.
15. **Closed assets blocked member removal and risked losing history — app bug.** The delete guard now counts only active manual assets. Before removing a member, closed assets assigned directly to them are reassigned to the household's self member, then flushed before the member row is deleted. A DB/API test verifies active assets still block deletion, the closed asset survives, and its details remain available. Accounts and `HoldingLot` have no closed/status field, so their linked rows remain blockers.
16. **A just-left person could be stuck on onboarding's final step without a profile — app bug.** If `/v1/me` has no profile while the stored draft says `done`, onboarding now routes back to `household` and repairs the draft. The test verifies the household form can save the profile and then reach the ready step.
