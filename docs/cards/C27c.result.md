### Functions and view

- `app_household_role(uuid)` validates the selected household against the active grant; its pinned search path and revoked public access prevent header-only access.
- `app_accept_invite(text)` validates the token hash, email, expiry, and use state, locking the invite row so acceptance is single-use. All invalid invite cases return the same error.
- `app_merge_into_household(uuid)` permits only the current partner to move their rows, preserves the grantee's self member, returns per-table counts, and is idempotent.
- `default_self_member_for_owner()` now selects the logged-in partner's linked household member and rejects cross-household member IDs.
- `audit_household_write()` records cross-user row writes with `actor_user_id`. `mark_user_deleting()` and `clear_user_deleting()` suppress misleading audit rows during user deletion cascades.
- `household_people` is a security-barrier view exposing only household member display names and roles to an active household grant.

## Rework 1
